# 修改指南

## 分區與食材

- `app/page.tsx`：分區列表、冷藏／冷凍／常溫排列與網站標題。現有排列使用陣列切片，調整分區順序時需要同步檢查畫面。
- `app/api/state/route.ts`：分區驗證、舊名稱轉換及儲存格式。
- `app/food-catalog.ts`：食材選項、別名與預設單位。
- `app/kitchen.ts`：單位、烹調設備、食譜結構與庫存配對。
- `app/layout.tsx`：頁面標題與描述。
- `app/globals.css`：版面與色彩。

既有資料中的分區改名需要遷移；只改畫面標籤可能使舊資料無法顯示或儲存。

## 資料庫

`db/schema.ts` 定義資料表，`drizzle/` 保留建表遷移。庫存及食譜共用一筆版本化 JSON，價格使用另一筆紀錄。API 以版本號避免同時編輯覆蓋；遇到衝突時會載入新資料並請使用者重做操作。

`template-kitchen-v1` 是資料表內的固定紀錄鍵，不是登入憑證。每個部署必須綁定獨立資料庫。不要把固定紀錄鍵當成保護個資的機制。

若新增登入功能，需要一併處理庫存、價格及其他相關 API 的授權，不可只隱藏前端按鈕。

## 公開原始碼

只分享原始碼、空白結構及參考資料。不要上傳 `.git/`、`.env*`、`.wrangler/`、`.sites-runtime/`、`node_modules/`、`dist/`、資料庫備份、個人食譜、網站 ID 或憑證。

公開前執行測試與建置，檢查壓縮檔內容。第三方授權檔必須保留。
