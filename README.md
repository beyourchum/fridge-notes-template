# 冰箱小日子｜空白網站模板

建立自己的冰箱管理網站，記錄食材、食譜和補貨清單。保留現成介面，從空白資料開始；你可以請 ChatGPT 協助安裝及修改。

## 我需要準備什麼？

- 能讀取專案、執行程式的 ChatGPT／Codex 環境，或自己的電腦與 Node.js 22.13 以上版本。
- 要讓手機及其他裝置一起使用，需要支援後端與資料庫的網站託管環境。
- 使用 ChatGPT Sites 部署時，需要帳號具備 Sites 功能；可用性與費用依服務提供者及帳號而定。

下載檔案或把它上傳為 GPT 知識，不會自動啟動網站。ChatGPT 協助建置；食材資料儲存在網站的資料庫。

## 交給自己的 ChatGPT

1. 下載這個儲存庫的 ZIP 並解壓縮，或將儲存庫複製到自己的電腦。
2. 在能操作檔案及執行程式的環境中開啟專案資料夾。
3. 貼上 [啟動指令](START-HERE.md)，讓 ChatGPT 檢查環境並協助啟動。
4. 先確認空白頁面能新增、修改及重新載入食材，再開始輸入自己的資料。

## 功能

- 冷藏、冷凍與常溫分區，食材數量、常備數量及到期日。
- 調味料有／沒有勾選、補貨清單與採購文字。
- 食譜材料、步驟、選配材料及庫存配對。
- 文字、圖片 OCR 與網址食譜匯入；匯入內容需人工確認。
- 台灣當季蔬果參考、手動價格紀錄及外部推薦資料。

庫存、食譜與手動價格初始皆為空白。食材選項及當季資料是內建參考資料，不代表你家已有的庫存。外部網站可能暫時無法讀取。

## 在自己的電腦啟動

在專案根目錄依序執行：

```sh
npm ci
npm run build
npm run db:init
npm run dev
```

開啟終端機顯示的本機網址。`db:init` 只會在本機建立缺少的資料表，可以重複執行。開發伺服器只供本機使用。

```sh
npm test
```

執行現有食材、食譜匯入及選配材料測試。框架細節見 [原始 starter 文件](docs/STARTER.md)。

## 資料與共用範圍

每個部署使用自己的 D1 資料庫；同一部署的訪客共用一個冰箱。本模板沒有逐使用者登入隔離，能開啟網站的人可以查看及修改庫存、食譜與價格。自用部署應使用託管平台的私人存取設定；若要多人各自擁有私人冰箱，需要另行實作登入及資料隔離。

本機資料儲存在 `.wrangler/state/`，不會隨 GitHub 原始碼同步。備份本機資料時，先停止網站，再複製整個 `.wrangler/state/` 資料夾；還原時使用相同版本程式並停止網站後操作。雲端資料請使用託管平台提供的資料庫備份／匯出功能。更換裝置或清除資料夾前先備份。

## 發布自己的網站

請 ChatGPT 使用 Sites，以這份模板建立新的網站及獨立 D1 資料庫。`.openai/hosting.json` 刻意不含網站 ID；由建立新網站的流程填入新 ID，並套用 `drizzle/` 的資料表遷移。

GitHub 用來分享原始碼。此版本需要伺服器 API 及資料庫，無法直接作為 GitHub Pages 靜態網站執行。其他託管方式需要自行配置相容的 Worker 與 D1 綁定。

## 調整自己的冰箱

把想要的分區、設備與名稱告訴 ChatGPT。分區目前同時用於畫面、食材選項及 API 驗證，修改時須一起調整；請參考 [修改指南](docs/CUSTOMIZE.md)。
